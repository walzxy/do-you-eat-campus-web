# 项目任务：开发「今天吃了么」移动端网页应用的第零界面

你是一名资深前端开发工程师和 UI/UX 设计师。请根据以下要求，为校园美食决策应用「今天吃了么」开发第零界面（今日状态选择页）。

**目标：尽可能还原参考设计图的视觉风格，同时实现真正可交互、可运行、适配手机屏幕的网页界面。不要只生成静态图片。**

## 一、开发前要求

1. 先检查当前 VS Code 工作区中的项目结构、已有代码、框架、依赖和路由。
2. 优先沿用项目已经使用的技术栈和组件，不要擅自重建项目，不要覆盖已有代码。
3. 如果项目尚未初始化，再选择合适的前端技术方案。
4. 本次只实现第零界面，不要擅自开发首页、转盘、社区、个人中心等其他页面。
5. 先简要说明准备修改哪些文件，再进行实现。
6. 不要只提供代码片段；需要将代码实际写入对应文件，并确保项目能够运行。

## 二、产品信息

- 产品名称：今天吃了么
- 页面名称：第零界面 / 今日状态选择页
- 产品定位：面向大学生的校园食堂选餐应用
- 核心功能：让用户选择今天的身体状态，后续选餐功能根据该状态优先推荐更合适的菜品。
- 视觉关键词：温暖、简洁、治愈、轻盈、现代、亲切。
- 设计参考：Apple 系统 UI 的简洁布局、清晰层级、舒适留白和圆角卡片设计，并融入温暖的橙色主题与可爱的食物插画。

## 三、视觉设计规范

### 1. 配色

采用暖白色作为背景，橙色作为主色，避免大面积使用高饱和度颜色。

建议使用以下 CSS 变量：

- 页面背景：`#FFF8EF`
- 主橙色：`#FF873D`
- 深橙色：`#E96F24`
- 浅橙色背景：`#FFF0DF`
- 卡片背景：`#FFF4E8`
- 正文颜色：`#292621`
- 次级文字：`#947968`
- 边框颜色：`#F2D7BE`
- 白色：`#FFFFFF`

主按钮可以使用从 `#FF963F` 到 `#FF7835` 的柔和橙色渐变。

这些颜色应集中定义为 CSS Variables，便于整个项目统一修改。

### 2. 背景与整体布局

- 使用暖白色背景，而不是纯白色或深色背景。
- 页面四角可以使用非常浅的橙色有机曲线或柔和色块装饰。
- 整体布局采用单列主容器，内容居中。
- 使用充足的留白，避免密集排列。
- 视觉层级清晰，不要添加过多装饰。
- 所有卡片和按钮采用自然、柔和的圆角。
- 阴影轻微、低对比度，不使用厚重的投影。
- 页面应像精致的原生手机应用，而不是传统后台管理系统。
- 优先保证真实手机上的浏览体验，不要将桌面端页面简单缩小。

### 3. 顶部区域

在页面顶部显示产品名称：

**今天吃了么**

具体要求：

- 位于页面上部中央。
- 使用较大字号、粗体中文字体。
- 字体颜色为明亮橙色。
- 可以添加简洁的手绘风格下划线或小装饰线。
- 字体应亲切、有活力，但不能过度卡通化。
- 下方显示副标题：

「选个好状态，吃顿好饭吧～」

副标题使用柔和的棕灰色，字号明显小于主标题。

### 4. 中央食物插画

在副标题下方、状态选择区域上方放置一个可爱的橙色米饭碗插画。

插画要求：

- 一个装着白米饭的橙色碗。
- 碗具有简单、友好的笑脸。
- 配有两根筷子。
- 使用柔和的立体感、细腻高光和轻微阴影。
- 整体以橙色、奶油白和浅棕色为主。
- 可以使用轻盈的浅橙色背景形状衬托插画。
- 插画应精致可爱，但不能抢过页面主标题和状态选择区域的视觉重点。

优先使用项目中已有的插画资源。如果没有，可以使用可控的 SVG 插画或本地静态图片资源。不要依赖随机图片网站或运行时不稳定的外部图片链接。

如果暂时无法制作精细插画，可以先使用简洁的矢量插画占位，并保证整体视觉协调。

### 5. 今日状态区域

中央插画下方设置状态选择区域。

标题：

「今日状态」

说明文字：

「选择你今天的身体状态，系统会为你推荐更合适的菜品」

标题使用深色粗体，说明文字使用棕灰色。

提供以下五种状态：

1. 正常
2. 生病
3. 上火
4. 肠胃不适
5. 生理期

每个选项设计为一个独立的圆角卡片。

布局参考：

- 第一行：正常、生病
- 第二行：上火、肠胃不适
- 第三行：生理期

手机端采用两列网格布局，最后一个选项自然靠左排列。

每个卡片包含：

- 一个简洁的线性图标。
- 状态文字。
- 选中时显示清晰的勾选标记。

图标建议：

- 正常：笑脸图标。
- 生病：温度计或医疗十字图标。
- 上火：火焰图标。
- 肠胃不适：简洁的胃部或腹部图标。
- 生理期：水滴图标。

优先使用项目中已有的图标库；如果没有，可以使用 Lucide 等轻量级图标方案。

卡片默认状态：

- 背景为浅奶油橙色。
- 无明显粗边框。
- 图标与文字使用柔和的深棕色或橙色。

卡片选中状态：

- 边框变为主橙色。
- 背景略微加深为浅橙色。
- 图标和文字使用更明显的橙色或深橙色。
- 卡片右侧显示圆形橙色勾选标记。
- 通过轻微的颜色变化反馈选中状态，不使用夸张的缩放动画。

### 6. 底部主按钮

在状态卡片下方放置一个横向的大按钮。

按钮文字：

「确定」

设计要求：

- 宽度接近页面内容区的全部宽度。
- 高度适中，方便单手触控。
- 橙色渐变背景。
- 白色粗体文字。
- 大圆角，视觉轻盈。
- 按钮与上方卡片保持适当距离。
- 点击时提供轻微的视觉反馈。
- 底部留出足够的安全区域，避免被手机底部手势条遮挡。

不要让按钮固定定位后遮挡页面内容。可以根据实际页面高度选择自然布局或安全的底部区域。

### 7. 字体规范

- 使用系统字体栈，优先使用设备上的中文系统字体。
- 推荐 CSS：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 主标题字号约为 36–48px，具体根据屏幕宽度调整。
- 区域标题字号约为 24–28px。
- 正文约为 15–18px。
- 状态文字约为 17–20px。
- 按钮文字约为 20–24px。
- 使用合理的字重与行高，避免所有文字都过粗。

以上尺寸均为参考值，需要通过响应式设计适配实际屏幕。

## 四、交互逻辑

### 1. 状态选择

用户可以点击任意一个状态卡片。

选择状态后：

- 卡片立即显示选中样式。
- 其他卡片恢复未选中样式。
- 当前页面暂定为单选。
- 默认选中「正常」。
- 点击其他选项时更新当前选中状态。

### 2. 确定按钮

点击「确定」后：

1. 保存用户当天选择的状态。
2. 为后续进入首页提供状态数据。
3. 如果项目已有路由，进入已有的首页路由。
4. 如果首页尚未开发，不要擅自生成完整首页。可以先设置一个清晰的路由占位或通过开发环境中的临时提示验证跳转逻辑。
5. 不要伪造登录、数据库写入或云端保存成功的结果。

在没有接入后端时，可以先将状态保存在前端临时状态中，并清楚标注尚未接入云端存储。

### 3. 当日状态规则

产品规则：

- 今日状态当天选择一次后保留。
- 当天再次打开页面时，应读取当天已经选择的状态。
- 次日需要重新选择。
- 日期计算应采用产品约定的时区，暂时可使用设备本地日期，并将其封装为独立函数，方便以后调整。
- 如果后续接入登录与云端数据库，应将状态与用户账号、日期关联。
- 不要使用 AI 推测用户的身体状况或自动更改用户选择。

### 4. 动效

可以添加少量柔和动效：

- 页面内容淡入。
- 状态卡片轻微颜色过渡。
- 按钮按下时的轻微反馈。

禁止：

- 夸张弹跳。
- 大量粒子特效。
- 复杂的持续动画。
- 影响手机性能的高频动效。

## 五、响应式设计

必须优先适配手机端。

要求：

- 支持常见 iPhone 和 Android 手机屏幕。
- 支持不同宽度的手机浏览器。
- 正确处理刘海屏、状态栏和底部安全区域。
- 使用 `viewport` meta 标签。
- 使用 CSS Grid 或 Flexbox 构建布局。
- 不允许出现横向滚动条。
- 在较矮的手机屏幕上，允许页面自然滚动，不得强行压缩所有内容。
- 在较宽的屏幕上，可以限制主内容的最大宽度，使页面仍然具有手机应用的比例感。
- 避免通过大量绝对定位来实现整个页面。
- 使用触控友好的交互区域。
